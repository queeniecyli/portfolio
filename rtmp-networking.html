RTMP-In Networking

Technical Implementation 5 min read

The Challenge: Critical Protocol Update for Company Events

At Macquarie Group, live streaming is essential for broadcasting high-stakes corporate events such as the Annual General Meeting (AGM), town halls, and executive communications to global audiences. The organisation relies on RTMP (Real-Time Messaging Protocol) to stream professional broadcast content into Microsoft Teams Live Events for company-wide distribution.

Microsoft announced a critical infrastructure change: the RTMP ingest protocol for Teams Live Events would be updated, requiring changes to both the RTMP domain endpoint and port configuration. The announcement came approximately one month before the AGM, leaving a narrow window to complete the migration. Without this update, all scheduled live events—including the upcoming AGM—would fail to stream, creating a high-impact business continuity risk.

The challenge was to coordinate a time-sensitive technical migration across network engineering, event production teams, and broadcast operators within a 2-week execution window to prevent service disruption for mission-critical corporate communications.

What is RTMP and Why It Matters for Corporate Events

RTMP (Real-Time Messaging Protocol) is a TCP-based protocol designed for transmitting live audio and video from broadcasting software to streaming platforms. For enterprise events, RTMP enables professional broadcast workflows with dedicated cameras, graphics overlays, and multi-source mixing—capabilities not available with standard webcam-based conference tools.

Why Organisations Use RTMP for Live Events:

Broadcast-quality production with professional cameras and mixers
Real-time graphics, lower thirds, and branding overlays
Multi-source switching between cameras, slides, and videos
Reliable low-latency streaming to large audiences

Real-World Use Cases at Macquarie:

  • Annual General Meeting (AGM): High-stakes shareholder communications requiring broadcast-quality production
  • Executive Town Halls: CEO and leadership updates distributed to 20,000+ global employees
  • Corporate Announcements: Financial results, strategic initiatives, and organisational updates
  • Training & Development: Large-scale learning events with professional presentation quality

The Microsoft Protocol Update

Microsoft announced that the RTMP ingest endpoint for Teams Live Events would be migrated to a new infrastructure, requiring updates to both the server domain and port configuration. Failure to update configurations before the migration deadline would result in stream connection failures.

What Changed:

Previous Configuration (Legacy):
RTMP Server: rtmp://[old-domain].streaming.media.azure.net:1935
Port: 1935 (standard RTMP port)

New Configuration (Required):
RTMP Server: rtmp://[new-domain].ingest.streaming.mediaservices.windows.net:1936
Port: 1936 (updated port)
Domain: New Azure Media Services infrastructure

Business Impact if Not Updated:

  • Scheduled AGM broadcast would fail to stream to attendees
  • Executive communications disrupted for global workforce
  • Reputational risk from failed high-visibility events
  • Emergency mitigation requiring rapid troubleshooting during live events

Network Configuration Complexity:

The organisation had existing firewall rules configured for the legacy RTMP infrastructure (port 1935, old domain). The migration required both updating existing rules and adding new rules for the new protocol configuration—coordinated across network engineering teams to ensure seamless transition without impacting scheduled events.

Technical Architecture & Dependencies

Understanding the full technical stack was critical to coordinating the protocol migration without service disruption.

Architecture Components:

1. Network Ingress Layer

  • Existing rules: Firewall configuration for legacy RTMP (port 1935, old domain)
  • Updated rules: Modified firewall policies for new RTMP endpoint (port 1936, new domain)
  • Network segmentation to isolate streaming traffic
  • DDoS protection and rate limiting
  • Load balancing for high-availability streaming

2. Security & Authentication

  • Stream key authentication for authorised broadcasters
  • TLS encryption for secure transmission (RTMPS)
  • Access control policies and user provisioning
  • Monitoring and logging for security auditing

3. Microsoft Teams Live Events Platform

  • Teams Live Events configuration with RTMP ingest enabled
  • Azure Media Services backend infrastructure
  • CDN distribution to global employee audience
  • Recording and archival through Teams platform

Migration Strategy & Execution

With approximately one month's notice before the AGM and only 2 weeks allocated for execution, the protocol migration required coordinated action across multiple stakeholder groups with minimal margin for error.

My Role: Technical Coordination & Communication

  • Impact Assessment: Identified all affected events, broadcast workflows, and technical dependencies requiring updates
  • Network Engineering Coordination: Worked with network teams to update existing firewall rules and add new rules for port 1936 and new domain whitelist configurations
  • Stakeholder Communication: Notified event production teams, broadcast operators, and AV vendors about required configuration changes
  • Documentation Updates: Revised technical guides, runbooks, and configuration templates with new RTMP parameters
  • Testing & Validation: Coordinated pre-event testing with production teams to validate new configuration before AGM
  • Contingency Planning: Developed rollback procedures and alternative streaming methods in case of migration issues

Cross-Functional Team Coordination:

Successfully delivering this migration in 2 weeks required coordinating across multiple technical and operational teams, each with critical dependencies on the RTMP infrastructure.

Key Learnings: Managing Technical Migrations Under Pressure

This 2-week protocol migration highlighted critical lessons about managing technical changes that impact business-critical systems under tight deadlines.

Key Takeaways:

  • Proactive Monitoring of Vendor Updates is Essential: Microsoft's announcement could have been missed; monitoring platform updates and technical bulletins is critical for avoiding surprises
  • Impact Assessment Must Be Immediate: Understanding which events, systems, and teams are affected allows for rapid prioritisation and resource allocation
  • Network Dependencies Are Often Invisible: Existing firewall rules, port configurations, and domain whitelists aren't always documented; understanding what rules needed updating versus what new rules needed adding was critical to the migration timeline
  • Clear Communication Prevents Confusion: Broadcasting teams needed simple, actionable instructions, not technical jargon; providing side-by-side configuration comparisons accelerated adoption
  • Testing Before High-Stakes Events Is Non-Negotiable: Pre-event rehearsals with the new configuration validated the migration and gave operators confidence before the AGM
  • Cross-Functional Coordination Drives Success: This wasn't a one-team effort; network engineering, security, event production, and broadcast operators all had to align within tight timelines
  • Documentation Is Your Safety Net: Updated runbooks and configuration guides ensured that future events wouldn't be affected, even with operator turnover
  • Legacy Infrastructure Requires Careful Migration: Updating existing firewall rules while adding new ones required coordination to avoid breaking current functionality while enabling new capabilities
  • Time Pressure Demands Parallel Execution: With only 2 weeks before the AGM, tasks had to run in parallel—network updates, documentation, and stakeholder communication happened simultaneously rather than sequentially
